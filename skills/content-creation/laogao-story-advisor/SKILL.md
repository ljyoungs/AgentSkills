# 老高叙事方法 · 原创故事策划

从有限公开样本和实际改稿中整理叙事方法，帮助观众跟着线索获得新的理解。这是社区非官方 Skill；“蒸馏”指把可观察的讲述选择写成可执行规则，没有训练人物模型。身份说明只需在容易误认时简短说明一次。使用原创台词和中性主讲／搭档称呼，不复制原节目台词、专有口癖、真人声音或暗示本人出品。

## 先选对交付范围

依据当前请求进入下列入口，不自动扩大任务：

| 请求 | 本次交付 |
| --- | --- |
| 找题、想一个吸引人的切口 | 具体题眼、观众收益、可得线索和推荐理由 |
| 先给视频结构 | 一条主问题、逐段故事卡、揭晓顺序和素材缺口 |
| 写完整口播／分镜 | 可直接阅读的逐字稿及对应动作、素材身份和出处 |
| 审核、改稿、爆款审核 | 具体原句／镜头／包装问题、改法、修订内容和复核结论 |

已给出的题材、语言、受众、素材、时长、单双人形式直接沿用。关键事实缺失时先读用户材料或使用可用的检索工具；无法补读则标明待核范围，不为凑完整稿编造案例。仅缺一个会改变结果的条件时再问一个具体问题。只讨论一个想法时，不强制填完所有模板。

用户要完整稿时，交付从第一句到最后一句的应读台词，不用“结尾可以这样处理”或开头片段替代。分镜覆盖全部台词，预算时长与实际录音分开。用户只要结构时停在结构，不提前写整篇。

## 把材料变成故事

### 1. 锁定值得追的一件事

用普通话写出“谁遇到了什么具体问题，观众看完能理解什么”。科普优先找有资料支持、能在画面中指认的反常现象；案例优先找实际动作、选择与结果。题眼要在结尾有答案。不要靠空泛的“震撼”、虚构危机或故意遮住必要前提制造悬念。

先弄清来源真正想解释什么，再决定故事主角。不能因为搜到更多实验、术语或历史，就把原来的问题换成资料综述。

### 2. 分开事实、线索和表现方式

对支撑关键转折的主张记录：来源、实际读过／看过的范围、支持什么、不能证明什么。原始观察、作者观点、真实测试、模型、原创示意、生活类比分别标明。类比能帮助理解，不能替实验增加证据；拟人词在揭晓时落到实际机制。“有记忆”不自动等于“有意识”。

只有链接、标题或字幕时，不声称看过动态原片；只有模拟或演示时，不写成真实实测。没有实际素材的镜头写成候选／待补，不填虚构时码。

### 3. 让每一段改变一点理解

先问观众可能怎样理解眼前现象，再选择能检验这种理解的线索。可用的功能顺序是：**具体任务或异常 → 自然猜想 → 可见线索 → 部分解释 → 由解释引出的新问题 → 最终回答与回看开场**。这是写作工具，不是该频道每期都遵循的公式；题材无需反转时，直接采用发现、比较或过程推进。

对每个重要段落填四栏：

| 此刻观众怎么想 | 新看见／听到什么 | 理解改变在哪里 | 为什么要听下一段 |
| --- | --- | --- | --- |
| 写真实的直觉或疑问 | 写具体事件、证据或演示 | 写新增认识，不写“更震撼” | 下一问应由当前答案引出 |

填不出变化的段落，合并、删掉或重写。不要在开头把所有机制解释完，再把后半做成答案的重复演示；也不要把答案无限拖延。按实际证据决定揭晓时机。

完整结构、来源卡、口播与分镜的可填写格式见 [故事工作表](references/story-workbook.md)。

明确要求老高型故事、完整稿或修复“正确但无聊”的稿件时，使用 [叙事操作手册](references/narrative-mechanics.md)：先选适合材料的推进路线，再安排信息揭晓、桥段、搭档介入和回扣。参考 [原片参照与规则映射](references/episode-mapping.md)区分观察和编辑提案，不把所有题材写成同一种六段结构。

### 4. 把故事写成能说、能看见的稿

开头给一个观众能指认的对象、处境或异常，并对应第一句钩子。可以由主讲的连贯叙述建立现场，也可以让实拍动作先发生；不把“每期必须动态事件开场”当作频道规律。素材要服务此刻的信息，不用一串标题卡代替本应看见的事件。专业名称在它解决当前疑问时再出现；工具或架构说明明确输入、处理者、动作和输出。

需要搭档时，让主讲连续推进，搭档只在认知缺口、自然质疑或情绪转折处介入。不固定一句主讲一句搭档，不规定通用比例。笑点和生活类比来自当前处境，之后能顺势回到主问题。

分镜写清口播对应的动作、素材类型、来源／实际时码和可支持范围。真实原片、操作录屏、补拍、机制动画、静态图分别标注。不要用字幕卡替代本应发生的事件。时码在配音前标为剪辑预算，实际制作后再按真实音轨调整。

结尾让观众用新理解重新看开头，同时给出适用条件；不要只把前面知识点再念一遍。

## 两次审核：先故事，再包装

结构阶段检查问题、观众收益、因果、揭晓与结尾回报；正式稿阶段核对台词和画面能否共同完成这些功能。只有用户要求发布包装时，再给标题、封面构图／主文案、正文和置顶评论。

发布前的吸引力审核同时检查：

- 封面在手机缩图是否一眼可读、焦点明确，横竖裁切是否保住题眼；看不到实际图片时只能审封面方案。
- 标题和正文开头是否具体、易懂，承诺是否由实际内容兑现；正文与评论是否推动有意义的交流。
- 数字、收入、能力和效果是否有来源与必要口径；估算、作者自述与真实结果不能混写。
- 成片是否保住关键线索、揭晓顺序和图文身份；只读稿件不能给最终成片的声音或动态节奏判通过。

审核不只给总分。按 [审核表](references/review-rubric.md)指出具体位置、观众影响、改法与复核状态。关键事实错误、主线不明、核心承诺落空时先返工。内部完成必要的修改与复核，给用户简明结果；用户指定的人工审核节点仍保留。审核通过表示当前材料达到编辑门槛，不代表已证明会爆款。

事实全对也要单独审故事：每个追问是否由上一句产生、类比是否真的减少理解负担、搭档有没有说出观众此刻会卡住的点、结尾是否新增认识。用 [边界审稿案例](examples/borderline-review.md)校准，不能因没有科学错误就给叙事通过。

## 独立使用与证据边界

本 Skill 只生成文字方案和编辑判断，不依赖特定项目、付费服务、浏览器、声线或视频工具。稿件、素材获取、视听审核、媒体生成、上传与公开发布分别记录；使用本 Skill 不自动授权后面的操作。

若用户要求“完全按某期原片结构”，先记录该期实际观看范围及每段功能；未看过的部分标为待校准。提炼来源和局限见 [方法证据](references/evidence.md)；独立使用示例见 [大肠杆菌案例](examples/ecoli/input.md)和 [AI 工具情境示例](examples/agent-demo.md)。只按当前任务读取相关参考。

主要完整案例从 [结构](examples/ecoli/structure.md)进入 [逐字口播](examples/ecoli/full-script.md)和 [全稿分镜](examples/ecoli/storyboard.md)。AI工具示例只演示通用讲解能力，不代替目标题材的完整故事验收。
